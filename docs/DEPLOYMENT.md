# Deploying to Render

The repo includes `render.yaml`, so Render builds the whole service from a
Blueprint — no manual service configuration.

## One-time setup

1. **Push this repo to GitHub** (private repo recommended). The local repo is
   already committed; create an empty repo on GitHub, then:
   ```bash
   cd ~/Downloads/amex-receipt-app
   git remote add origin git@github.com:<org>/<repo>.git
   git push -u origin main
   ```
2. **Render Dashboard → New → Blueprint** → connect the GitHub repo →
   Render reads `render.yaml` and shows the `amex-receipt-api` service.
3. During creation Render prompts for the secret env vars
   (`sync: false` ones):
   - `JOTFORM_API_KEY` — the Jotform key (Full Access)
   - `APP_BASE_URL` — leave blank for now; set after first deploy
   - `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` — leave blank until email is ready
     (reminders run in logged "simulated" mode without them)
4. Deploy. When it's live, note the service URL
   (e.g. `https://amex-receipt-api.onrender.com`) and:
   - set `APP_BASE_URL` to that URL (Environment tab) — it's used in the
     signed links inside reminder emails
   - put the same URL into `mobile/src/api/client.js` → `API_BASE_URL`
5. Seed the production admin user: Render Shell tab →
   `node scripts/seed.js`, or create users via the API. **Change the seeded
   passwords immediately.**

## Why the Starter plan (not Free)

- The **persistent disk** (`/data`) holds the SQLite database and receipt
  images; free instances have no disks and lose all files on every restart.
- Free instances **sleep when idle**, which would stop the in-process cron
  jobs (hourly reminders, 15-min Jotform sync).

## Operational notes

- `PORT` is injected by Render automatically; the server reads it.
- `JWT_SECRET` is generated by Render once and persists.
- Health checks hit `/api/health`.
- Pushing to `main` auto-deploys (`autoDeploy: true`).
- Backups: Render disks support snapshots; for belt-and-suspenders, copy
  `/data/app.db` off-box periodically (it's a single file).
- Scale-up path: move to Render Postgres + S3/R2 for images when volume
  justifies it (see docs/ARCHITECTURE.md).

## SMTP suggestion

The org uses Google Workspace (operations@woodstockarts.org): either an
app-password SMTP via `smtp.gmail.com:587`, or a free-tier transactional
provider (Brevo, Resend, Postmark) for better deliverability of reminder mail.
